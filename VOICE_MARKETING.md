# VOICE_MARKETING.md — Home Page, Feature Pages, Templates

## Identity

ModulaCMS marketing sounds like a product page that respects your time. Not a sales pitch. Not a startup deck. Not a SaaS landing page with gradient backgrounds and abstract illustrations.

The reader is a professional developer evaluating whether this CMS fits their project. They don't want to read source code on a landing page. They want to know what it does and what they get.

## Core Voice

**Neutral.** Describe what the product does. Don't argue why it's better than alternatives. Don't call out competitors. Don't editorialize. The home page presents ModulaCMS on its own terms. Opinions and comparisons live on the story page (see SITE_ROADMAP.md).

**Approachable.** Talk to professional developers, not computer scientists. Explain what the product does for them, not how it works internally. "Two commands to start" beats a code block showing the init function's internals.

**Specific.** Replace enthusiasm with numbers. "27 MB binary" is more compelling than "incredibly lightweight." "No user limits" beats "scales with your team." Every claim should have a fact behind it.

**Sparse.** Fewer words. Short sentences when they work. Let whitespace and the design system do the heavy lifting. If you can cut a sentence and the meaning survives, cut it.

## Anti-AI Rules

These prevent marketing copy from reading like it was generated by a language model.

### Max one bulleted list per page section
Bullet lists are the default output of every AI tool. Use prose instead. One feature list per section is acceptable — convert everything else to sentences.

**Not this:**
```
Benefits:
- Fast deployment
- No dependencies
- Simple configuration
- Easy scaling
```

**This:**
```
Deploy it in seconds. No runtime dependencies, no package manager,
no configuration files to hunt down. It scales horizontally
because it's stateless.
```

### No em dashes for pauses
Use commas, periods, or restructure the sentence. Em dashes in marketing copy are an AI tell.

### No groups of three
Don't list three adjectives, three benefits, three comparisons in parallel. Two or four. Never exactly three.

**Not this:** "Fast, flexible, and free."

**This:** "Fast and free. Configure what you need."

### No summary sections
Don't end a page section with "In summary" or "To recap." When you're done, stop.

### No superlatives without proof
Don't say "blazing fast" or "incredibly simple." Say "27 MB binary, two commands to start" and let the reader decide.

### Vary sentence and paragraph length
Mix single-sentence paragraphs with longer ones. Uniform blocks of 3-sentence paragraphs read as generated.

### No emoji, no decorative symbols
No sparkles, checkmarks, rockets, or lightbulbs. The design system handles visual hierarchy.

## Tone Rules

### Features sell, code doesn't
A landing page filled with code blocks isn't approachable. Describe what the product does and why it matters. Save the code for documentation.

One exception: an install command is fine as a CTA. `modula init && modula serve` works because it demonstrates simplicity. But an API response JSON block on a hero section doesn't sell anything.

### Be specific, not enthusiastic
Replace excitement with specifics. Numbers, sizes, counts. Let the reader feel impressed on their own. Forced excitement reads as insecurity.

### Describe, don't compare
The home page presents what ModulaCMS does. Not what it does better than something else. Competitor comparisons, industry criticism, and design philosophy live on the story page (VOICE_BLOG.md).

### Use "you" and "your"
Address the developer directly. "Define your content model" not "Developers define their content models."

### Kill corporate filler on sight
These words mean nothing: leverage, empower, seamless, robust, cutting-edge, next-generation, enterprise-grade, best-in-class, game-changing, revolutionary.

Say what it actually does instead.

## Key Phrases

These have been written and approved. Use them as-is or adapt minimally:

- "Start with a REST API. Enable what you need. Nothing more."
- "Your framework already solves these problems. Your CMS shouldn't solve them again, differently."
- "All features. One binary. No tiers, no cloud lock-in, no upgrade prompts. Ever."
- "Single binary. No runtime. Stateless. Deploy it like infrastructure, not like a CMS."
- "ModulaCMS handles the infrastructure. You define the content."
- "The CMS answers: what is at this URL? The client decides: what do I do about it?"

## Checklist

Before publishing marketing copy:

- [ ] Could a developer skim this in 10 seconds and understand what the product does?
- [ ] Any code blocks that should be feature descriptions instead?
- [ ] Any comparisons to competitors? Move to the story page.
- [ ] Any bulleted lists beyond the one allowed per section? Convert to prose.
- [ ] Any groups of three? Break the pattern.
- [ ] Any superlatives without specific numbers behind them?
- [ ] Any corporate filler words? Replace with specifics.
- [ ] Does it sound like a SaaS landing page? Rewrite until it doesn't.
- [ ] Read it out loud. Does it sound like a product page that respects your time?
